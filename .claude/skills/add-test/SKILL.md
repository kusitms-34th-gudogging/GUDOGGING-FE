# 테스트 작성

규칙 내용은 문서가 원본. 이 스킬은 순서와 검증만 정함

- **대상은 요청에 적힌 파일만**. 대상이 없으면("테스트 짜줘"만) 작성하지 말고 어떤 파일인지 물어봄
- 여러 파일을 요청받으면 **한 번에** 진행: 모든 파일의 케이스를 한꺼번에 보여주고 확인 1번 → 전부 작성·검증 → 마지막에 파일별로 모아서 보고

- 단위·컴포넌트·화면 전환 → 아래 "단위 테스트"
- 실기기 핵심 여정 → 아래 "E2E"
- 어느 쪽인지 애매하면 `unit-test.md`의 범위 표로 판단 (Jest로 확인 가능하면 단위 테스트)

## 단위 테스트

1. `.claude/rules/unit-test.md`를 먼저 읽음 (테스트 파일이 아직 없으면 자동으로 안 불러와짐)
2. 대상 파일과, 그 파일을 쓰는 곳을 읽음
3. **테스트 대상 고르기**(`unit-test.md` 1번)로 케이스를 정하고, 사용자에게 보여주고 **확인을 받은 뒤** 작성 (확인 전엔 파일 만들지 않음)
   - 테스트할 것: 케이스 목록
   - 테스트하지 않는 것: 이유와 함께
   - 테스트할 게 없으면(판단이 없는 코드) 작성하지 않고 이유만 알림
4. `{대상 폴더}/__tests__/{대상 파일명}.test.ts(x)`에 작성. 대상은 `@/` 경로로 import
5. `pnpm test {테스트 파일 경로}` → 통과 확인
6. **망가뜨려서 확인** (`unit-test.md` 2번의 "실패할 수 있음")
   1. 대상 파일 내용을 그대로 복사해둠 (커밋 안 된 변경이 있을 수 있으니 `git checkout`으로 되돌리지 않음)
   2. 케이스마다 그 케이스가 지키는 코드를 최소한으로 망가뜨림 (예: `disabled` 전달 줄 삭제, 분기 조건 반대로)
   3. `pnpm test {테스트 파일 경로}` → **실패해야 함**. 통과하면 그 테스트는 가짜 → 고치거나 지움
   4. 복사해둔 내용으로 되돌리고, 원래와 같은지 확인
7. `pnpm lint && pnpm typecheck`
8. 보고: 작성한 케이스, 뺀 케이스와 이유, 케이스별 검증 표(`케이스 | 망가뜨린 코드 | 결과: 실패함 ✅ / 통과함 ❌ → 고침·삭제`)

## E2E

1. `.claude/rules/e2e-test.md`를 먼저 읽음
2. 실행 환경 확인: `maestro --version`, `java -version`, 시뮬레이터에 앱 설치 여부
   - 없으면 플로우는 작성하되 **실행 확인 안 됨**을 사용자에게 알리고 설치·빌드 방법 안내 (설치는 사용자 확인 후)
3. **E2E 대상 고르기**(`e2e-test.md`)로 Jest로 넘길 것은 빼고, 사용자 여정 하나만 정함. 여정 단계를 보여주고 **확인을 받은 뒤** 작성
4. `.maestro/{여정}.yml` 작성. 공통 단계(로그인 등)는 `.maestro/subflows/`로 빼서 `runFlow`
5. 선택자는 `id`(RN `testID`) 우선. 필요한 요소에 `testID`가 없으면 추가할 위치를 사용자에게 알림 (공통 컴포넌트가 `testID` prop을 안 받으면 prop 추가 필요)
6. 환경이 있으면 `maestro test .maestro/{여정}.yml` → 통과 확인 → 중간 단계의 `assertVisible`을 틀린 값으로 바꿔 실패하는지 확인하고 되돌림
7. 보고: 작성한 플로우, 추가가 필요한 `testID`, 실행 확인 여부
